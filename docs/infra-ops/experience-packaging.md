# Упаковка рабочего опыта

В портале установлен native Skill **«Упаковка опыта»**, ID `experience-packaging`.
Он помогает сохранять проверенные правила и рабочие процессы для повторного
использования в разных предметных областях.

## Использование

В рабочем диалоге сказать: «Давай оформим наш опыт как Skill».
Агент собирает доступные источники, уточняет существенные решения, выбирает
минимальный пакет и указывает, где он сохранён и что проверено.
Для повторения открыть новый чат с нужными доступами и описать рабочую задачу.

Сохранение не доказывает правильность. Проверьте пакет по исходным соглашениям,
включая пограничные случаи, затем результат в новом чате. Первичная генерация
в приёмке содержала смысловые ошибки; принят цикл с ревью и исправлением.
Точные массовые расчёты требуют проверенного кода; исполняемый пилот в этой
поставке не проверялся.

## Сопровождение

Канонический исходник — [experience-packaging.md](../../deploy/openwebui-skills/experience-packaging.md).
Правила упаковки находятся в нём; эта инструкция описывает его сопровождение.
Изменение файла в Git само по себе не обновляет портал.

1. Проверить изменённый `SKILL.md`, включая разбор YAML и описание триггеров.
2. Через штатный Workspace Skills editor/API обновить `experience-packaging`.
   Перед изменением перечитать текущую версию; при API-записи использовать
   `expected_version_id`. Сохранять прежнюю версию в native history.
3. Сверить отдельные native name «Упаковка опыта» и description с назначением
   и frontmatter. `update_skill_files` меняет файлы, но не отдельное description;
   `view_skill` это поле не возвращает. Проверять его через editor/API.
4. Сохранить READ для аутентифицированных пользователей (`user:*`); shared WRITE
   не выдавать. Права пользователей на создание, исполнение и публикацию пакетов
   этим Skill не расширяются.
5. Перечитать сохранённый текст и metadata, сравнить SHA-256 UTF-8 с LF
   с исходником. Проверить обычным сотрудником чтение без права редактирования.
   Для значимых изменений повторить затронутую предметную приёмку и новый чат.

Возврат инструкции — через native history с проверкой текущей версии.
Код и ресурсы пользовательских процессов принадлежат Terminal-пакетам;
Workspace supporting files автоматически туда не устанавливаются.
Их выпуск и совместимость с накопленными данными проверяются отдельно.
