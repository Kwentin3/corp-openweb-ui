# Помощь по порталу и работе с ИИ

Справка работает в обычном чате через native Knowledge, Skill и системные
настройки существующих моделей OpenWebUI 0.12.2. Нового профиля модели, сервиса,
расписания или изменения ядра для неё нет. Текущая квалификация и оставшиеся
шаги записываются только в [GOAL](../reports/2026-11-18/PORTAL_HELP_GOAL.md).
Этот runbook не объявляет завершённой пользовательскую UI-приёмку.

## Как пользоваться

В обычном сохранённом чате с квалифицированной моделью спросить, например:
«Как получить Word по приложенной заметке?» или «Помоги поставить задачу ИИ:
мне нужно письмо заказчику по протоколу встречи». Помощник читает Skill и
подходящую тему, даёт выполнимые шаги, пример и существенные ограничения.
Отдельно выбирать модель справки или загружать справочник не требуется.
Обычная понятная задача выполняется без навязанного обучения.

Чтение справки не даёт сотруднику права менять бюджеты, общую библиотеку,
настройки или чужие данные. Вопрос «как пользоваться» не запускает эти операции.
Исторические проверки, кандидат и действующая возможность различаются в темах;
текущий личный доступ и остаток бюджета проверяют соответствующие native tools.

## Источники и владельцы

| Элемент | Канонический источник / назначение |
| --- | --- |
| Шесть тем | `deploy/openwebui-knowledge/portal-help/*.md`: работа с ИИ, Office, шаблоны, диктовка/записи, бюджеты, упаковка опыта |
| Правила помощи | `deploy/openwebui-skills/portal-help.md`, native Skill ID `portal-help` |
| Обнаружение в чате | `deploy/openwebui-skills/portal-help-discovery.txt` |
| Обновление | `scripts/sync-portal-help.py`, обёртка штатного `oikb==0.6.0` |
| Native Knowledge | ID `4ac92c03-4254-4666-98e1-6fb3557e0391`, marker `[managed:portal-help]` |

Git владеет принятыми текстами; оператор применяет их к отдельной native базе.
Knowledge владеет хранением, обработкой, поиском и ACL. Skill содержит только
правила помощи и supporting file `references/knowledge-index.md`: названия,
пути, актуальные native File ID и SHA-256. Копии корпуса в Skill нет.
Модель читает выбранную тему через `view_knowledge_file`; если такого tool нет,
Skill описывает ограниченное чтение через `grep_knowledge_files` с явной границей.
При attached Knowledge поиск может ограничиваться приложенными источниками,
поэтому индекс указывает конкретные File ID нужной help-базы.

Общие grants базы и Skill — `user:* READ`, без shared WRITE. Native владелец
сохраняет свои права управления. Источники не должны содержать секреты или
материалы, закрытые от сотрудников. Отдельные операции сохраняют прежних владельцев.

## Совместимость общей модели с OCR

`gpt-6-luna` используется также для распознавания PDF. Правило справки в
`params.system` действует в обычном чате; OCR передаёт собственную инструкцию
через штатные native маршруты и изолирует чатовый system. Исправление
[PR #620](https://github.com/Kwentin3/corp-openweb-ui/pull/620) от 26.11.2026
разрешает этот параметр в проверке OCR-адаптера. Другие inference overrides
и переадресация базовой модели по-прежнему запрещены.

При изменении настроек общей Luna проверять и обычный чат, и конечный OCR-запрос.
Ошибка `Luna OCR requires its direct native model without parameter overrides`
возникает до бюджетной подписи и вызова провайдера; сама по себе она не означает
исчерпания денег. Диагностика, актуальный hash Function, серверная приёмка и
порядок обновления/отката описаны в [runbook OCR](luna-ocr.md).

## Применение принятого изменения

Редактирование Git само по себе ничего не развёртывает. Автоматической загрузки,
daemon или расписания сейчас нет. После принятия изменений оператор запускает
синхронизацию и проверяет результат. Нужны установленный `oikb` версии 0.6.0,
Python 3.11+ и токен владельца managed Skill с правом записи в указанную Knowledge.
Токен хранится в защищённом UTF-8-файле: одна строка raw bearer, без `Bearer `.
Не передавать его аргументом, в чате, Git или receipt.

На Windows все команды выполняются через общий executor. Пример dry-run ниже
предполагает, что защищённый token-file и каталог private receipts уже существуют;
заменить локальные пути на подтверждённые оператором. Запускать из корня checkout.

```powershell
C:/Users/Администратор/.agents/windows-execution/agent-exec.v3.exe inline --owner portal-help-sync --shell powershell --timeout 300 --command-base64 ([Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes(@'
$ErrorActionPreference='Stop'
python scripts/sync-portal-help.py `
  --url https://gpt.alpha-soft.ru `
  --token-file D:/private/portal-help-token.txt `
  --knowledge-id 4ac92c03-4254-4666-98e1-6fb3557e0391 `
  --receipt D:/private/portal-help-dry-run.json `
  --dry-run
exit $LASTEXITCODE
'@)))
```

Проверить planned changes. Для применения выполнить ту же managed-команду без
`--dry-run`, с отдельным `--receipt`. Если `oikb` не в PATH, передать `--oikb`
с точным путём. `--source-dir` и `--skill-source` позволяют выбрать материалы
другого проверенного checkout. Обычный Skill ID сохранять `portal-help`;
не направлять синхронизацию в чужую базу.

Обёртка проверяет marker, права и владельца; пустой или невалидный источник
отклоняется до изменения. `oikb sync` добавляет, заменяет и удаляет файлы только
в указанной dedicated базе. Обёртка ждёт `completed`, сверяет исходные байты,
непустой извлечённый текст, полное членство и native diff. Затем публикует Skill
с новым индексом через native compare-and-set версии и проверяет readback.
Неизменный Skill остаётся без новой версии. Успех: receipt `status=verified`,
`skill_published=true`, ожидаемые файлы/хеши и актуальный native Skill readback.

Смена File ID при замене допустима: именно поэтому индекс обновляется после
проверки базы. Последняя обязательная проверка — новый обычный чат: изменённый
факт читается из новой темы, а не из истории; повторный sync не создаёт дубликаты.
Примеры и критерии: [кандидат приёмки](../reports/2026-11-18/PORTAL_HELP_ACCEPTANCE_CANDIDATE.md).

## Ошибка и восстановление

`oikb` удаляет изменённый файл перед загрузкой замены. Ошибка может оставить
частично обновлённую Knowledge и старый индекс Skill; операции не атомарны.
При `unconfirmed`, timeout или отмене сначала проверить завершение своего RunId
и дерева, затем native членство, статусы обработки, diff и текущую версию Skill.
Не повторять конфликтующий запуск и не считать отсутствие нового Skill откатом базы.

После установления состояния исправить причину и повторить тот же источник.
Для возврата содержания взять предыдущий принятый Git-выпуск корпуса и Skill
в отдельном checkout и применить той же обёрткой. Восстановленные файлы могут
получить новые File ID; старый индекс нельзя возвращать отдельно от Knowledge.
Сохранить прежние receipts и проверить новое чтение. Чужие Knowledge/Skills не менять.

## Подключение модели и удаление

В существующей ordinary text-модели discovery-блок добавляется к прежнему
`params.system` штатной настройки модели. Сохранять остальной system, все params,
meta, ACL и provider route; новый model ID не создавать. Точное состояние читать
через `GET /api/v1/models/model?id=...`: `/models/list` не показывает все строки
настроек базовых моделей. Если у каталожной модели ещё нет сохранённой native
записи, штатная настройка сохраняется с тем же ID и без нового provider route.
Глобальный `DEFAULT_MODEL_PARAMS.system` в проверке
не вошёл в initial provider context и был восстановлен. Выбор native skillIds
или default Skill сам по себе не гарантирует чтение инструкции.

После добавления проверить обычного сотрудника и фактический контекст: вызов
`view_skill`, чтение темы и соответствующий источнику ответ. Правило подключено
к 11 текущим текстовым моделям/профилям; поведение проверяется репрезентативно,
а не объявляется одинаково качественным для любой модели. Точный охват — в GOAL.
Worker/admin/service с `builtin_tools=false` исключены; image-only и Arena
требуют отдельной квалификации. Наличие имени в каталоге не доказывает готовности.

При откате подключения удалить только точный блок между
`[portal-help-discovery-v1]` и `[/portal-help-discovery-v1]` из затронутых моделей,
проверив актуальное состояние перед записью и сохранив все прочие параметры.
Knowledge и Skill сохраняются для восстановления. Если отдельно поручено полное
удаление функции, сначала убрать подключения, затем удалить только подтверждённые
managed Skill/Knowledge и принадлежащие им ресурсы штатными API. Не удалять общие
источники, чужие файлы, rollback assets и приватные evidence вне этого поручения.
