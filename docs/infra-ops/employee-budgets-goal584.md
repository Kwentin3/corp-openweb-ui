**Внедрён и проверен в production. Runtime source: `5458b49fa44ce1659a6eac8625dfa43fd6880533`.**
Согласовано: две компактные суммы
«Ответ: … · Чат: …», разговорное чтение собственного бюджета и расходов через
штатный Workspace Tool, уборка заменённой большой карточки «Стоимость: детали».

Без нового финансового хранилища, сервиса и оркестратора.
После исследования штатных возможностей и community пользователь явно разрешил
узкий патч интерфейса Open WebUI: суммы должны быть внизу после длинного ответа.
Контракт — необязательный `status.data.position = "after_content"`; без него
существующее размещение сохраняется. Патч включается в реестр обновлений.

Проверка точного исходника установленного Open WebUI 0.12.2 (`6a18585f`)
подтвердила: status и общие embeds находятся над текстом, под ответом доступны
штатные citations/code executions и кнопки; `ⓘ` показывает usage JSON.
Реальный renderer осмотрен на PNG с явно условными суммами и заблокированными
записями: это эскиз, не приёмка стоимости. Вариант сверху не принят пользователем:
после длинного ответа статистика должна быть рядом с его концом и кнопками.

Найден точный upstream запрос [#31886](https://github.com/open-webui/open-webui/issues/31886),
перенесённый в [discussion #31897](https://github.com/open-webui/open-webui/discussions/31897).
Предложенный `position: after_content` — эскиз API, не подтверждённая возможность
установленной версии. Там предложен community Event «Interface Toggles».
В [#31970](https://github.com/open-webui/open-webui/discussions/31970) его автор
описывает этот класс расширений как внедрение scripts/styles через общие static
assets с зависимостью от DOM-разметки. Исходник самого Interface Toggles из каталога
не получен; runtime-совместимость с 0.12.2 не проверялась. Отдельно в
[#23049](https://github.com/open-webui/open-webui/issues/23049#issuecomment-4131809709)
разработчик подтвердил намеренное размещение общих embeds сверху.

Проверен фактический код community
[Token Usage & Cost Display](https://github.com/SmetDenis/openwebui-token-usage-display/blob/main/usage_display.py)

самостоятельного footer placement в этом пути нет. Упоминание «below» в описании
не доказывает размещения под ответом на нашей версии. Итоговое решение пользователя —
один явный патч контракта размещения, без DOM-обхода; данные остаются из существующего
authoritative reader. В существующее обсуждение отправлены

## Согласованный результат и границы

LiteLLM — единственный владелец расходов, денежных лимитов, резервирования и SpendLogs.
Общая серверная интеграция связывает вызов с сотрудником, чатом и ответом, включая
вызовы помощников. Новый конвейер, использующий этот общий путь, не добавляет свою
финансовую логику. Служебные задачи используют отдельного плательщика.

Сотрудник видит стоимость ответа и накопленную стоимость чата на момент чтения.
Администратор меняет месячные лимиты и распределение по моделям через готовую
форму в чате с серверной проверкой прав и штатным подтверждением.
Если Usage отсутствует, расход неизвестен и блокируется только соответствующая
модель данного сотрудника. Подтверждённый ноль отличается от неизвестного расхода.

Разрешены исходники, рефакторинг и изолированный стенд. Пользователь отдельно
разрешил узкую поправку исходной Usage/завершения потока только на стенде, без
deployment, новых журналов и новой тестовой инфраструктуры. Ранее разрешённый
calendar-floor patch двух функций сохраняется отдельно и без изменений.
Production, платные API, реальные тарифы/лимиты и изменения рабочих маршрутов
требуют отдельного согласования. Office/Tasks/Skills/Files/STT, полный контекст
модели, reasoning, права и данные сохраняются.

## Политика, сохранённая для продолжения

- Существующий компонент → штатная возможность → тонкая адаптация → новый код только при доказанном разрыве.
- Один владелец финансового состояния; обновляемое ядро; без финансовой логики в конвейерах.
- Проверки соразмерны изменению; принятые результаты повторяются только при новых значимых входах/свидетельствах.
- Production и реальные деньги не входят в стендовое разрешение.
- Разрастание тестовой инфраструктуры отдельно зафиксировано в глобальный backlog; это не условие текущей поставки.
