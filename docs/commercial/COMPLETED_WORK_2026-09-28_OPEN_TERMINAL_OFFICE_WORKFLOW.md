# Дополнение к отчёту для заказчика: универсальная обработка Office-файлов в Linux

Дата: 28 сентября 2026 года.
Статус: решение выпущено для пользователей, проверка в обычном чате пройдена.

Этот документ дополняет отчёт
[об упрощении интеграции OfficeCLI](COMPLETED_WORK_2026-09-28_OFFICECLI_NATIVE.md).
Предыдущая поставка и её фиксированная версия не переписываются.

## Зачем понадобилось дополнение

OfficeCLI хорошо выполняет штатные операции над Excel, Word и PowerPoint, но не
является универсальной средой для любого многоэтапного задания. В частности,
перенос большого числа листов со значениями и ресурсами требовал массовой
обработки, которой не было среди готовых команд.

В OpenWebUI подключён официальный Open Terminal — управляемая Linux-среда, в
которой агент может исследовать копии входных файлов и выполнять необходимые
скрипты. OfficeCLI сохранился как основной специализированный инструмент; Terminal
добавляет общий путь для операций, которых в нём нет. OpenWebUI и Open Terminal
не форкались.

## Что изменилось для пользователя

| Выполненная работа | Результат для заказчика |
| --- | --- |
| Подключён официальный Open Terminal | Агент может выполнять недостающую обработку в серверной Linux-среде |
| Добавлен общий порядок многоэтапной работы | Агент сначала составляет полный перечень частей, фиксирует план и проверяет комплектность результата |
| Реализована передача вложения из чата в Terminal | Агент работает с отдельной копией; исходный пользовательский файл не изменяется |
| Реализована публикация результата из Terminal | Готовый документ возвращается обычным вложением OpenWebUI с реальным идентификатором и ссылкой |
| Ограничены повторные попытки | Временное чтение повторяется один раз; запись вслепую не повторяется |
| Исправлена работа ссылок | Агент использует только ссылку, подтверждённую фактической публикацией файла |
| Добавлены проверки завершения | Успех означает проверенный файл и полный результат, а не только выполненную команду |

Решение не добавляет отдельный редактор документов, второй чат или новый
механизм хранения. Пользователь продолжает работать в обычном чате OpenWebUI.

## Что проверено после выкладки

Проверка выполнена от имени обычного пользователя через реальный интерфейс
OpenWebUI. Файлы обрабатывались в Linux, а не в локальном Windows-окружении.

- **Excel:** создана новая книга без формул, проверены лист, итоговые значения
  `3000`, `1500` и `4500`, а также возможность повторно открыть результат.
- **Word:** сохранены исходные заголовок, код и таблица; добавлен заданный текст;
  результат повторно открыт и проверен через `python-docx`.
- **PowerPoint:** сохранены исходный слайд и его содержимое; добавлен второй слайд;
  оба слайда повторно открыты и проверены через `python-pptx`.
- Во всех трёх сценариях исходные файлы остались побайтно неизменными.
- Все результаты опубликованы как штатные вложения OpenWebUI с фактическими
  `result_file_id` и ссылками скачивания.
- Для двух обычных пользователей подтверждены разные домашние каталоги Terminal.

При первом прогоне внутренний запрос к Terminal попал во внешний прокси и
получил HTTP 502. Внутренний адрес добавлен в `NO_PROXY`, после чего те же
пользовательские сценарии завершились успешно. После исправления оба контейнера
были здоровы, перезапусков и ошибок 5xx в проверяемом маршруте не было.

## Границы решения

Текущий бесплатный многопользовательский режим подходит для согласованной
доверенной команды: у пользователей разные домашние каталоги, но общий Linux-
контейнер, ядро, сеть, список процессов и пул ресурсов. Это условие было отдельно
согласовано для действующих 23 пользователей. Для взаимно недоверенных групп
потребуются отдельные изолированные Terminal-окружения.

Проверка подтверждает рабочий общий маршрут и три репрезентативных документа. Она
не обещает автоматическую безошибочную обработку любого Office-файла. Макросы,
защищённые документы, внешние связи и сложные формулы могут потребовать уточнения
или другого способа переноса. В такой ситуации агент должен перечислить найденное
ограничение и согласовать изменение метода, например перенос вычисленных значений
вместо формул.
