# Дополнение к отчёту для заказчика: работа с существующим шаблоном PowerPoint

Дата: 30 сентября 2026 года.
Статус: доработка выпущена, проверка в обычном чате пройдена.

Этот документ дополняет [отчёт о нативной интеграции OfficeCLI](COMPLETED_WORK_2026-09-28_OFFICECLI_NATIVE.md)
и [отчёт о резервном маршруте Open Terminal](COMPLETED_WORK_2026-09-28_OPEN_TERMINAL_OFFICE_WORKFLOW.md).
Он описывает только последующую работу с существующим PPTX. Состав и оценки прежних
поставок не меняются.

## Результат для пользователя

Когда к запросу на изменение приложена презентация, агент использует её как
исходный документ, даже если пользователь не произнёс слово «шаблон». Результат
создаётся как новая версия: исходный файл не перезаписывается, а не затронутые
запросом слайды, изображения и редактируемые объекты сохраняются. В следующем
сообщении можно продолжить работу с последней опубликованной версией без
повторной загрузки файла.

| Выполненная работа | Результат для заказчика |
| --- | --- |
| Уточнён выбор операции в обычном чате | Приложенный PPTX изменяется как копия; пустая презентация создаётся только при явном запросе на независимый документ |
| Использовано штатное копирование слайда OfficeCLI | Новый слайд наследует редактируемые фигуры, таблицу, изображение и оформление существующего слайда |
| Добавлена проверка исходника до правки | Если в выбранном PPTX нарушены связи с изображениями, агент сообщает конкретную поломку пользователю, не выдаёт повреждённый результат и предлагает исправный прежний файл либо восстановление копии |
| Уточнена проверка результата | Агент сверяет объекты и их расположение через OfficeCLI, проверяет отображение слайда и продолжает с фактического идентификатора последней опубликованной версии |

Основной маршрут остаётся прежним: обычный чат OpenWebUI → штатные команды
OfficeCLI → обычное вложение с результатом. Open Terminal применяется только
при установленном пробеле в возможностях OfficeCLI. Новый редактор презентаций,
хранилище файлов или отдельный пользовательский профиль не добавлялись.

## Проверка на фактическом материале

В исходном пользовательском чате первым в списке оказался ранее созданный
результат, а не первоначальная корпоративная презентация. У этого результата
проверка выявила девять нарушенных связей с изображениями на шести слайдах.
Исходная корпоративная презентация из 13 слайдов проверку прошла. При отдельной
проверке в обычном чате агент объяснил повреждение пользователю и предложил два
пути продолжения; новую версию повреждённого файла он не опубликовал.

На исправном исходнике в обычном чате с GPT-6 Sol агент скопировал слайд,
изменил редактируемый заголовок, проверил его отображение и выдал PPTX из
14 слайдов. Следующие запросы обработаны на основе последней выданной версии
без повторной загрузки. Независимая сверка подтвердила сохранность 13 исходных
слайдов по визуальному представлению, всех 15 медиафайлов побайтно и
редактируемых фигур, таблицы и изображения на добавленном слайде. В последнем
проверочном ходе использовались штатные операции OfficeCLI без Terminal.

Проверки кода охватывают выбор исходного файла по истории чата, отказ при
повреждённом PPTX, копирование слайда и правку опубликованной версии. Оба
обязательных CI-проверки PR прошли. Во время первого прогона исправного файла
произошёл краткий перезапуск OpenWebUI; опубликованный файл сохранился,
последующие ходы завершились. Причина перезапуска этой проверкой не установлена.

## Границы и подтверждение

Проверка подтверждает описанный сценарий на фактическом шаблоне и указанной
модели. Она не означает, что любые нестандартные возможности PowerPoint или
любая модель обрабатываются без потерь. Повреждённый файл не восстанавливается
автоматически: дальнейший источник или восстановление копии выбирает
пользователь после объяснения проблемы.

Основание расследования — [задача #545](https://github.com/Kwentin3/corp-openweb-ui/issues/545).

Сырые пользовательские сообщения и сами презентации в GitHub не публикуются.

Новые часы, стоимость, оплату или договорную приёмку этот отчёт не
