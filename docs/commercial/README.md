# Коммерческие документы: оглавление поставок

Он помогает найти документы по конкретной поставке и объясняет их назначение.
При появлении следующего этапа сюда добавляется ссылка на новый отчёт;
состав прежних поставок не заменяется новым.

отчётам как ещё один объём. Они объединяют ранее зафиксированные работы
по нужным заказчику направлениям. Исходные отчёты сохранены; рефакторинг
транскрибации уже имеет самостоятельное обоснование и не пересчитывался.

Поздние работы без установленной часовой оценки не следует автоматически
считать ни бесплатными, ни дополнительной задолженностью. Исключение по
статусу расчётов — обновление платформы: его закрытие прямо подтверждено
представителем исполнителя 19.10.2026 и отражено в соответствующей сводке.

## Как сохраняется история

Новый предъявляемый объём получает отдельный датированный отчёт, а не
`README2` и не новую редакцию отчёта о другой поставке. Один отчёт может
объединять несколько функций или один этап большой функции. Последующая
доработка ссылается на исходную поставку и отделяет свои часы от прежних.
Уточняющая сводка явно отмечает, что не создаёт нового предъявления и не
меняет оценки исходных отчётов.

Редактура черновика фиксируется в Git. После использования отчёта в подписанном
акте его не переиспользуют для следующих работ; необходимое уточнение выпускают
отдельным документом со ссылкой на исходную версию и явным описанием отличий.

Дата в имени сама по себе не фиксирует содержимое. Для акта используют
постоянную ссылку `blob/<полный SHA коммита>/docs/commercial/COMPLETED_WORK_...md`,
а не ссылку на `main` или на README. Относительные ссылки на подробные отчёты
открываются из того же коммита. Ставка, стоимость и платёжные документы
хранятся вне GitHub.

Прежние адреса сводки и `STAGE2_*` оставлены как короткие указатели,
а не параллельные отчёты.
