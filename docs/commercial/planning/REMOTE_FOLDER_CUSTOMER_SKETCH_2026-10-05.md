# Эскиз для заказчика: работа агента с папками на компьютере пользователя

Дата: 5 октября 2026 года.  
Статус: продуктовая хотелка и предварительный вариант реализации; не выполненная поставка и не согласованная оценка работ.

Связанная задача: [Remote Folder — локальные папки пользователя через Open Terminal](https://github.com/Kwentin3/corp-openweb-ui/issues/552).

## О какой хотелке идёт речь

Есть понятный пользовательский сценарий: хочется, чтобы корпоративный портал мог работать не только с файлами, которые человек вручную загрузил в чат, но и с его обычными рабочими папками на компьютере.

Например, сотрудник один раз подключает к своему рабочему пространству папку **«Договоры»**, а потом в обычном чате пишет:

> «Разбери папку Договоры по таким-то критериям и подготовь сводку».

После этого агент сам работает с разрешённой папкой. Пользователю не нужно каждый раз собирать документы, загружать их на портал, скачивать результат и раскладывать всё обратно.

Если задача предполагает создание или изменение файлов, результат может появляться прямо в той же рабочей папке.

## Как это должно выглядеть для пользователя

Идея примерно такая:

1. Пользователь один раз подключает рабочий компьютер к корпоративному порталу.
2. В своём рабочем пространстве выбирает папки, с которыми агенту разрешено работать.
3. Для каждой папки можно задать понятный режим — например, только чтение или чтение и изменение.
4. После этого пользователь просто обращается к папке по имени в обычном чате.
5. Портал сам связывается с нужным рабочим компьютером и выполняет задачу.

При этом сам пользователь может открыть портал с другого компьютера, планшета или телефона. Важно не устройство, с которого открыт чат, а тот рабочий компьютер, где находится подключённая папка.

## Почему это выглядит реализуемо без большой новой системы

У нас уже есть Open Terminal — штатный механизм, через который агент умеет работать в командной среде, запускать программы и обрабатывать файлы.

Поэтому предварительная идея не в том, чтобы строить ещё одно файловое хранилище или копировать все папки пользователя на сервер.

На рабочем компьютере достаточно небольшого локального компонента, который:

- безопасно связывает компьютер с корпоративным порталом;
- сообщает, какие папки разрешены;
- даёт агенту правильный контекст: Windows или Linux, PowerShell или другая оболочка, какие инструменты доступны;
- поддерживает связь с Open Terminal;
- помогает вести историю того, что агент менял.

Сами ограничения доступа можно опирать на обычные права операционной системы: агент работает под отдельной служебной учётной записью и видит только те каталоги, которые ему разрешили.

## История изменений

Для такого сценария важно, чтобы агент понимал, что происходило с папкой раньше.

Например, если вчера он уже приводил часть договоров к нужному виду, следующая сессия должна иметь возможность увидеть эту историю и продолжить работу, а не начинать всё заново.

Для этого предварительно планируем использовать обычный локальный Git как техническую историю версий. Пользователю не придётся работать с Git самостоятельно — это внутренний механизм для агента и сопровождения.

При необходимости рядом может храниться короткая запись: какая задача выполнялась, какие файлы менялись и что осталось незавершённым.

## Чего специально не хотим делать

На этом этапе не видим смысла:

- делать отдельное файловое облако;
- синхронизировать все пользовательские папки на сервер;
- ставить на компьютеры полноценный второй OpenWebUI;
- строить собственный аналог Git;
- переделывать ядро OpenWebUI;
- создавать большую отдельную платформу для этой функции.

Логика обратная: максимально использовать то, что уже есть в OpenWebUI, Open Terminal, операционной системе и Git, а свой небольшой слой оставить только там, где действительно не хватает связи между ними.

## Что нужно проверить перед реализацией

Перед тем как превращать идею в полноценную поставку, нужно на небольшом стенде проверить несколько практических вещей:

- стабильную работу локального Open Terminal на пользовательском компьютере;
- несколько пользователей и несколько рабочих компьютеров одновременно;
- автоматическое восстановление связи после смены сети, сна или перезагрузки;
- ограничения доступа к разрешённым папкам;
- сохранение истории изменений;
- отсутствие влияния этой функции на обычные чаты и текущие офисные инструменты.

Если эти проверки проходят, функция выглядит относительно компактной: большая часть нужных механизмов уже существует, а нам остаётся связать их в понятный пользовательский сценарий.

## Предварительный результат для пользователя

В идеальном виде всё сводится к простому действию:

> **Подключил рабочую папку один раз → дальше агент может работать с ней из обычного чата.**

Это пока эскиз направления. Он не устанавливает сроки, стоимость или окончательный технический состав реализации.
