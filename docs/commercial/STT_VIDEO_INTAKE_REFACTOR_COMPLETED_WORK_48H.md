# Отчёт для заказчика: доработка загрузки видео и транскрибации / 48 часов

Дата: 2026-09-25.
Статус: выполненная доработка, включённая в рабочий OpenWebUI.

Этот документ описывает отдельную доработку уже существующей функции
транскрибации аудио и видео. Оценка трудоёмкости — **48 человеко-часов**.
Это оценка объёма законченной инженерной работы, а не поминутный табель.
Ставка и денежная стоимость здесь не определяются.

## Что было

Пользователь прикреплял видео к чату и нажимал «Отправить». Только после
этого система извлекала из видео звук, отправляла его на расшифровку и
возвращала текст в чат. Базовая возможность транскрибации уже работала:
её предыдущая поставка описана в [PR #517](https://github.com/Kwentin3/corp-openweb-ui/pull/517).

Но видеофайл мог оставаться на сервере, если обработка не завершалась.
При больших файлах отдельные участки обработки также создавали лишнюю
нагрузку на оперативную память. Пользователь не видел понятного ожидания,
если нажимал «Отправить», пока файл ещё готовился. Для нас это было
неудобно в эксплуатации: видео занимает много места, а для этой функции
нужна только его аудиодорожка.

## Что изменили

- Перенесли извлечение звука на момент загрузки файла. Пользователь
  прикрепляет видео, и сервер сразу готовит из него MP3.
- После успешной подготовки видео заменяется аудиофайлом в том же
  вложении чата. Исходный видеофайл удаляется **до** транскрибации.
- Если извлечь звук не удалось, система делает ещё две попытки: одну
  сразу, последнюю примерно через 7 минут. После третьей неудачи видео
  удаляется, а пользователь получает понятную ошибку.
- Если пользователь нажал «Отправить» во время подготовки, чат сообщает,
  что готовит аудио, и отправляет сообщение автоматически по завершении.
- Передачу и обработку больших файлов перевели на потоковую работу через
  диск: сервер не загружает видео целиком в оперативную память.
- Обработали старые видеофайлы, которые остались после прежнего сценария:
  доступные записи перевели в аудио, непригодные и лишние видео удалили.
  Добавили восстановление незавершённой обработки после перезапуска.
- Проверили новый сценарий в рабочем OpenWebUI, включая получение
  расшифровки, и обновили эксплуатационные документы.

## Как это работает теперь

1. Сотрудник прикрепляет видео в обычном чате. Подготовка звука начинается
   сразу, даже если сообщение пока не отправлено.
2. В чате появляется подготовленный аудиофайл; исходное видео удаляется
   с сервера.
3. Сотрудник нажимает «Отправить». Если аудио ещё готовится, он видит
   сообщение об ожидании. После завершения отправка происходит сама.
4. Система расшифровывает аудио и возвращает результат в тот же чат.

Если сервис расшифровки временно недоступен, подготовленный MP3 остаётся
для повторной попытки; хранить исходное видео для этого не требуется.
Если в видео нет пригодной аудиодорожки, после трёх попыток вложение
не отправляется, а видео удаляется. Поддержка любого существующего
видеоформата не обещается: файл должен быть доступен для обработки сервером.

## Трудоёмкость

| Работа | Часы |
| --- | ---: |
| Разбор прежнего сценария, остатков видео и причин нагрузки на память | 6 |
| Потоковая загрузка и серверная подготовка больших медиафайлов | 12 |
| Жизненный цикл видео: замена на аудио, три попытки, удаление и восстановление после сбоя | 12 |
| Поведение чата при ожидании и автоматическая отправка | 6 |
| Перенос старых вложений, развёртывание и проверка в рабочем контуре | 8 |
| Актуализация документации и итоговая сверка | 4 |
| **Итого** | **48** |

В эти 48 часов входит **только описанный рефакторинг**. Первоначальная
разработка STT, обработка расшифровок по шаблонам, Office Tools,
расширение диска VPS и другие работы сюда повторно не включены.
