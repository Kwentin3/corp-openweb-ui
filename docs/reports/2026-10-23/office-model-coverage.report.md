# Охват OfficeCLI пользовательскими моделями — 23.10.2026

## Объём и установленная причина

Проверены фактические каталоги OpenWebUI 0.12.2 под администратором и отдельным
обычным пользователем, все сохранённые модельные профили, установленный
`officecli_auto_attach_filter`, его Valves и штатное подключение `officecli`.
Список доступных провайдеру моделей не принимался за пользовательский каталог.

Исходный пользовательский запрос на Word-файл закончился созданием заметки.
В истории были `view_skill`, поиск баз знаний и `write_note`; OfficeCLI не
вызывался. Точный ID `deepseek-flash` отсутствовал в `target_model_ids`.
Установленный Filter возвращал такой запрос до добавления `server:officecli`.
Прочитанная инструкция `artifact-workflow` сама по себе инструменты не подключает.

## Матрица охвата

Обычному пользователю доступны восемь моделей: семь текстовых и одна для
генерации изображений. Администратору дополнительно видны Arena и Argon.

| Модель | Автоподключение до → после | Проверка в этом выпуске / решение |
| --- | --- | --- |
| `deepseek-flash` | нет → да | DOCX/XLSX/PPTX созданы; итоговые файлы проверены и скачаны из UI. Для исправления содержания Word и ссылок потребовались уточнения |
| `gpt-5.4-mini` | да → да | Контрольный DOCX создан, проверен и скачан из UI |
| `gpt-5.6-luna` | да → да | Действующие настройки сохранены; новая файловая квалификация не заявляется |
| `gpt-6.1-sol` | да → да | Действующие настройки сохранены; новая файловая квалификация не заявляется |
| `models/gemini-3.5-flash` | да → да | Действующие настройки сохранены; новая файловая квалификация не заявляется |
| `models/gemini-3.6-flash` | да → да | Действующие настройки сохранены; новая файловая квалификация не заявляется |

| `models/gemini-4-argon` | нет → нет | Видна администратору, отсутствует в каталоге обычного пользователя; доступ не расширялся |
| `arena-model` | нет → нет | Административный составной режим, не отдельная прямая пользовательская модель |

Отсутствие function calling у Nano Banana подтверждено
[официальной карточкой Google](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1?hl=en).
Для DeepSeek использован фактический ID каталога `deepseek-flash`;
[официальная документация](https://api-docs.deepseek.com/) также рекомендует
этот ID и описывает старое имя `deepseek-v4-flash` как совместимый legacy alias.

В реестре 215 сохранённых профилей, из них девять активны. Активный сохранённый
`deepseek-v4-flash` не появляется в текущем пользовательском или административном
каталоге доступных моделей. Он не включался в OfficeCLI и не удалялся. Неактивные профили,
включая специализированные Pipes, не активировались. Прежние разрешённые ID,
которые сейчас не видны пользователю, сохранены без расширения grants.

## Минимальное изменение

Через штатный `POST /api/v1/functions/id/officecli_auto_attach_filter/valves/update`
к прежнему `target_model_ids` добавлен только `deepseek-flash`. Остальные Valves,
порядок прежних ID, Active/Global, Tool Server и модельные grants сохранены.
Состояние считано обратно. Код Filter, core, провайдеры и образы не менялись;
перезапуска и сборки не было. Действующий Valve остаётся владельцем списка:
в source не создаётся второй актуальный список модельного каталога.

Установленный Filter совпал с source исходной рабочей копии
`9679655c19553bf74b42c135dfd53e30f94305e8`. LF SHA-256 до и после:
`8417e8d64000ed3606e84086f3b75e2da6328dcd105fb3dccd300426220b60dd`.
Штатный Tool Server остаётся единственным: `officecli`, session auth,
внутренний `http://officecli-0122:8080`, существующий `user:* read`.
Инструменты фактического чата сообщают OfficeCLI 1.0.152.

Перед записью окончательный набор Valves исполнен на точном совпавшем Filter:
DeepSeek получает native function calling и `server:officecli`; запросы двух
прежних моделей дают прежний результат; исключённые модели, вспомогательные
tasks и запросы с явно переданными `tools` остаются у своего владельца.
Это проверка конфигурации, отдельно от продуктовой приёмки ниже.

## Файловая приёмка

Проводится через обычный Web UI под отдельным пользователем с ролью `user`,
на синтетическом коммерческом предложении: две услуги, 2 × 1500 = 3000 и
3 × 2000 = 6000, итог 9000; срок пять рабочих дней, аванс 50%, подпись,
контрольная строка `OFFICE-20261023`. Для XLSX требуются формулы, для PPTX —
ровно два слайда. Новая проверка не изменяет исходный пользовательский чат.

Получены нативные `result_file_id` и возвращённые инструментами `download_url`.
Четыре итоговых файла (три DeepSeek и контрольный DOCX) скачаны кликом по
обычным ссылкам/вложению в браузере. Перед скачиванием выполнен штатный signin
проверочного пользователя; и bearer-сессия, и cookie принадлежат роли `user`.
SHA-256 браузерных скачиваний совпали с File API и хешами в результатах OfficeCLI.

| Результат | Размер, байт | SHA-256 |
| --- | ---: | --- |
| DeepSeek DOCX, после точной правки | 6783 | `5963d349819f2714fa81210f46bac496a7a987fc04907777e4c1e1b91ec0f65d` |
| DeepSeek XLSX | 5435 | `90ba10b6b44c193afb15d4fcccff11b85241fdaf0884015b5b8a131a78220c6f` |
| DeepSeek PPTX | 16651 | `f6e78e49ee99e65ebfe03faeee0fcfb39b0619244b3de29bbafd6546b21da46d` |
| Контрольный DOCX, GPT | 5524 | `9f3336e8ca09b0dfaae291e554d1ea26d0880fd14c0046220009a610ee42f536` |

Независимо от текста модели проверены OOXML и сохранённые значения:

- В Word присутствуют все заданные разделы, обе услуги, цены, количества,
  суммы, клиент, срок, аванс, контрольная строка и подпись. В точном продолжении
  удалено не заданное исходными данными налоговое утверждение. Сравнение XML
  подтвердило сохранение остального содержания и форматирования; в изменённом
  абзаце поменялись `textId` и один неразрывный пробел, а также служебное время
  OfficeCLI. Итоговая версия отрисована и визуально проверена.
- В XLSX ровно один лист `Смета`, правильные исходные числа и формулы
  `D5=B5*C5`, `D6=B6*C6`, `D7=SUM(D5:D6)`. Сохранённые результаты равны
  3000, 6000, 9000; ошибок формул нет. Рендер итогового файла читаем.
- В PPTX ровно два слайда с заданными данными. Последняя правка затронула только
  XML второго слайда и `OfficeCLI.LastModified`; остальные части пакета
  байт-идентичны ранее отрисованной версии. Поэтому рендер первого слайда
  подтверждён сравнением частей, а второй проверен рендером конечного File ID.
- После точной правки Word File ID и байты Excel/PPTX не изменились.
  Контрольный GPT DOCX содержит ровно заданный заголовок и три абзаца и читаем
  на рендере. Все сохранённые модельные профили и grants, пользовательский
  каталог, исходник и флаги Filter совпадают с состоянием до изменения.

### Ограничения качества модели

Доступность инструментов подтверждена, но безошибочная первая выдача DeepSeek
не заявляется. Первый ответ потребовал 39 вызовов инструментов. Первое создание
XLSX атомарно отклонено из-за придуманного значения `border.top=thin;1F3864`;
модель прочитала справку и исправила запрос. Обнаруженные ей проблемы ширины
колонок и текстовых блоков устранены в её же обычном цикле OfficeCLI.

Потребовались два пользовательских уточнения: убрать добавленную без основания
фразу про НДС и исправить выдачу ссылок. Сначала адреса были оформлены как код,
а после просьбы о Markdown модель добавила посторонний домен. Эти внешние ссылки
не открывались. После явного уточнения модель выдала три правильных относительных
`download_url`, и каждый был скачан из UI. Первая карточка вложения показывала
последний выпущенный файл; это не принималось за наличие трёх доступных ссылок.
Новых обработчиков ссылок, скрытых retries и модельных обходов не добавляли.

Результат выпуска — устранён пропуск подключения. Это не сертификация любых
заданий, сложности документов или безошибочной работы всех моделей. Пять прочих
уже подключённых пользовательских текстовых моделей в этом выпуске не проходили
повторную файловую приёмку; их действующие настройки сохранены. Вспомогательное
действие «В Word», доступное отдельно от модельного function calling, не
использовалось как доказательство автоматического подключения OfficeCLI.

## Дальнейшее сопровождение

Выпуск настройки и исходной матрицы зафиксирован в
[PR #573](https://github.com/Kwentin3/corp-openweb-ui/pull/573), коммит
`ab917ae396035ac3dd20a59f4329be923cb89162`; обязательный Active CI завершился
успешно. Для последующих моделей в существующем runbook закреплён
[обязательный чек-лист добавления и замены модели](../../infra-ops/officecli-openapi-docx-release.md#добавление-и-замена-модели-обязательный-чек-лист).
Он задаёт минимальную настройку, три файловых задания, продолжение с последней
версии, проверку выдачи, статусы и откат. Автоматического подключения новых ID
или гарантии безошибочного первого ответа это не добавляет.

Матрица выше остаётся датированным результатом фактически проведённых проверок.
Новый чек-лист не означает, что ранее подключённые модели или этот срез задним
числом прошли дополнительные задания. Результат для заказчика и границы учёта
приведены в [отдельном дополнении](../../commercial/COMPLETED_WORK_2026-10-23_OFFICE_MODEL_COVERAGE.md).

## Evidence и откат

Приватные исходные ответы API, сессии, результаты инструментов, скачанные файлы
и изображения остаются вне Git в `local/office-model-coverage-20261023/`.
Репетиция — `rehearsal.safe.json`, readback — `activation.safe.json`,
проверка файлов и неизменности настроек — `verification.safe.json`,
предыдущее состояние — `rollback.private.json`. После проверки тестовый аккаунт
переведён в `pending`, его сессии отозваны; тестовые чаты и файлы сохранены как
evidence. Дополнительная вкладка закрыта, в исходной восстановлена сессия
администратора. Пароль и сохранённые токены проверки удалены из локального
пакета evidence. Для отката восстановить только
сохранённые прежние Valves через тот же штатный endpoint, предварительно проверив
отсутствие новых независимых изменений. Действующие source и флаги не переключать.
