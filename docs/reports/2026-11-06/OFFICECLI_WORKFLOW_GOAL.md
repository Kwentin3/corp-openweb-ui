# GOAL: native artifact-workflow перед записью OfficeCLI

Дата: 06.11.2026. Статус: в работе.

## Результат и границы

Обеспечить применение существующего `artifact-workflow` в обычном OfficeCLI-чате
до первой операции создания или изменения файла. Для большой задачи модель
использует native Tasks, продолжает от последнего результата и завершает работу
по критериям готовности. Методика остаётся в одном native Skill.

В поставке: минимальное изменение действующего Filter, проверки его перехода
к native Skills, выпуск Function с сохранением Valves/прав, приёмка протокола
«Ваниль» через обычный UI и безопасная уборка своей диагностики.
Не входят: core, новые оркестраторы, копирование методики в промпты,
переназначение прямых моделей на Terra-worker и переделка публикации файлов.
Строго одно вложение не является критерием: повторные правки должны быть
обоснованы конкретными дефектами.

## Приёмка

1. Проверить окончательный кандидат с действующими Valves и репрезентативной
   фактической веткой до внешнего запроса; native context содержит полный Skill,
   его правила Tasks/завершения, сохраняет пользовательский текст и прочие pins.
2. Проверить реальные инструменты и final provider-boundary payload существующим
   ограниченным capture до первой записи, включая историю, источники,
   инструкции, tool results и схемы Tasks.
3. Обычный UI, исходная форма и расшифровка: содержательный Tasks-план, сохранность
   формы и фактов, причины повторных правок, правильная цепочка File ID,
   проверка конечных страниц и настоящее UI-скачивание.
4. Обязательный CI на точном кандидате после содержательной локальной проверки;
   выпуск только проверенного source Function с native readback и rollback.
5. Выключить bounded capture, подтвердить отсутствие своих фоновых процессов,
   сохранить приватное evidence вне Git, закрыть task-owned временные ресурсы.

## Обязательные оставшиеся шаги
