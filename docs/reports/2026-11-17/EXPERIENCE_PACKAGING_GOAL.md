# GOAL: нативная упаковка проверенного опыта

Дата: 17.11.2026. Основной skill установлен; ограниченная приёмка завершена.
Поставка исходника и отчётов — [PR #596](https://github.com/Kwentin3/corp-openweb-ui/pull/596).
Единственная запись задачи; текущие merge/CI принадлежат native PR.

## Согласованный результат

Создать и внедрить в портал один общий skill упаковки проверенного опыта для
разных предметных областей: исследования, API, технические операции, данные,
разработка и другие повторяемые процессы. Office — возможный частный случай.

Пользователь просит сохранить опыт обычной фразой. Агент отбирает подтверждённое,
определяет необходимость skill/кода, выясняет существенные пробелы, сохраняет
инструкции и ресурсы у существующих владельцев, обеспечивает обнаружение,
предметную проверку, версии/исправления/возврат и продолжение в новом чате.

В поставку входят maintained source в `deploy/openwebui-skills/`, установленный
native Skill с READ для аутентифицированных пользователей и ограниченная
приёмка обычным сотрудником. Права создания/исполнения/публикации пользователей
не расширяются. Новый backend, router, реестр и интерфейс не создаются.

Основание: [аудит установленного стека](SKILL_EXPERIENCE_PACKAGING_AUDIT.md).
Последнее решение пользователя отменяет ограничение на Office/ежедневку.

## Ограничения и решения

- Изменяются только новый authoring Skill, его исходник и task-owned evidence.
  Независимые изменения корпоративных шаблонов и исходные рабочие чаты/данные
  сохраняются. Ежедневка не является обязательным пилотом.
- Workspace владеет текстовой методикой; Terminal — исполняемым файловым
  пакетом; изменяемое состояние хранится отдельно. Одна основная копия смысла.
- Авторский skill использует native create/update/read, existing permissions
  и native discovery. Глобальные Filters и core не меняются.
- Приёмка использует короткие синтетические данные. Первые проверки —
  representative input/schema и чтение actual context до платного запуска.
- До 8 содержательных пользовательских ходов первой серии; расширено до 10
  после обнаруженных смысловых ошибок и пропущенного начала capture нового чата.
  Повтор последнего входа нужен для фактического provider-context evidence.
  Отдельный ответ
  ограничивается 120 секундами наблюдения, с native Stop при превышении.
  По неопределённому исходу сначала проверяются native task/chat/skill/file
  состояния; слепые повторные генерации запрещены.
- Bounded provider capture только для собственных тестовых chat IDs: TTL до
  900 секунд, до 20 запросов на серию, без побочных title/tag задач. Capture
  выключается после наблюдения; private evidence не попадает в Git.
- Только последовательные короткие исполнения через существующую среду;
  фоновую работу и живой process ID между чатами не переносить.
- После приёмки удалить только точные тестовые chats/Skills/files по журналу
  созданных ресурсов. Продуктовый authoring Skill сохраняется.

## Критерии готовности

| ID | Обязательная проверка |
| --- | --- |
| A1 | Source/readback соответствуют установленному native Skill, name/description корректны |
| A2 | Обычная просьба об упаковке выбирает authoring Skill; существенный пробел выясняется |
| A3 | Подтверждённое сохранено, отброшенный подход/неизвестное не становятся правилом |
| A4 | Созданный личный skill доступен новому чату и даёт правильный не-Office результат |
| A5 | Посторонний запрос не вызывает упаковки/нежелательных записей |
| A6 | Код и ресурсы при необходимости используют правильного владельца, состояние отдельно; без выдуманной синхронизации |
| A7 | Исправления, native versions/CAS/metadata и возврат описаны применимо; полномочия соблюдены |
| A8 | Проверены actual model context, tool results и предметный результат; ограничения названы |
| A9 | Исходник поставлен отдельно от чужой работы; диагностика выключена и тестовые ресурсы убраны |

## Предметная приёмка и её границы

- Обычный UI-диалог выполнил создание, вопрос о существенном решении,
  последующую доработку через native `update_skill_files` и readback.
  После обратной связи модель исправила область конфликта, пересечение блоков,
  точность ID и удалила непроверенный виртуальный скрипт.
- Независимое ревью выявило ещё две ошибки: одинаковые CLOSED были объявлены
  открытыми в описании дубликата; нормализация статуса была ошибочно названа
  оформлением. Ведущий исправил шесть точных фрагментов обычным native API с CAS,
  без изменения metadata/ACL. Это явная редактура по ревью; она не считается
  успешной первичной генерацией. Native history сохраняет три версии пакета.
- Принятый тестовый пакет: `incident-queue-latest-status`, version
  `0124b0ac-7996-481b-b05d-50ad252a30bc`, SHA-256
  `b601dab43ec2d110c9a81ce6a15cfa1e806d42a21d938deb967a9f27aaec137a`.
  Private, владелец — тестирующий обычный сотрудник; supporting code отсутствует.
- Новый чат без старой переписки, без ID/подсказки правил: 16 строк, 10 инцидентов.
  Native discovery вызвал `view_skill` сохранённого пакета. Оба прогона дали:
  очередь EV-10/EV-12/EV-a (3); CLOSED/прочий точный статус (4); конфликт EV-8/EV-13
  (2, включая конфликт раньше максимума); без корректного времени EV-11 (1).
  Некорректных строк 2, включая EV-12, который остаётся в очереди.
  Регистр ID, дубликат CLOSED и точный OPEN/lower-case open различены правильно.
- Исходный быстрый ответ нового чата закончился до включения capture.
  Тот же вход повторён через обычное UI «Попробовать снова» под scoped capture:
  два provider requests, без старой переписки. Повтор проверяет контекст,
  а не маскирует неудачный результат.
- One-shot точность упаковки не подтверждена: три исходных генерации отклонены.
  Подтверждены native UX, discovery, версии и применение **после предметного
  ревью и исправления**. Этот Skill не гарантирует устранение галлюцинаций.
  Большой детерминированный workflow требует проверенного исполняемого пакета;
  в этой поставке такой пилот не создавался и не заявляется проверенным.
- Общая авторская инструкция остаётся 130 строк, без доменных правил инцидентов,
  новых сервисов и универсального реестра. Предметная проверка обязательна.
