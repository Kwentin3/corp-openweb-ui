# Broker Reports: единый текущий конвейер

Дата: 2026-08-20  
Статус: `STRATEGIC_STOP` — механизм таблиц доказан, весь GOAL пока не закрыт.

## Суть

Для Broker Reports оставлен один рабочий маршрут:

`PDF → нормализация → Canonical → Gate 3 → Gate 4 → Gate 5`.

VLM только указывает координаты таблиц. Текст, строки, столбцы и значения читает PDFPlumber. Legacy не используется как fallback; две старые функции на сервере выключены.

## Что оказалось важным

- Сетка с буквами и цифрами не нужна: координаты PDF уже являются общим языком VLM и PDFPlumber.
- Уточнение «это брокерский отчёт с несколькими независимыми таблицами» полезно как контекст, но не является источником данных.
- Разные таблицы нельзя объединять по смысловому предположению. Объединять можно только доказанное продолжение одной таблицы на следующей странице.
- Canonical хранит таблицы отдельными узлами; финансовый смысл появляется только после границы нормализации.
- Legacy-маршрут не является страховкой. Ошибка должна завершаться явным fail-closed статусом.

## Найденные ошибки и исправления

1. Текущий маршрут после Gate 3 перескакивал сразу в Gate 5. Сервер остановил его с `gate4_cache_missing`. Добавлен обязательный вызов штатного владельца Gate 4.
2. Gate 4 считал техническую запись исходного PDF вторым бизнес-документом. Область Gate 3/4 ограничена документами, у которых есть Canonical или Gate 3-аннотации.
3. Контрольный скрипт проверял старые названия табличного профиля и ложно помечал корректный Canonical как ошибку. Проверка переведена на единственный текущий профиль.
4. Старый текст контрольного запроса запрещал продолжение после Gate 1. Контекст заменён на запрос единого текущего маршрута без Knowledge/RAG и legacy.

## Проверка реальным PDF

Исходник: один настоящий шестистраничный брокерский отчёт. Один проход на страницу, без скрытых повторов, best-of-N, смены провайдера и ручной правки.

Результат нормализации:

- найдено 14 физических областей таблиц;
- восстановлено 12 логических таблиц;
- две пары областей правильно признаны продолжением таблиц между страницами;
- независимые таблицы не слиты;
- 198 строк и 2032 ячейки перенесены в Canonical;
- все 2979 выбранных ссылок на исходные значения учтены;
- пропущенных и повторно учтённых ссылок нет;
- позиции ячеек и значения между табличной проекцией и Canonical совпали без расхождений;
- страница без таблиц правильно оставлена без табличной области;
- OCR/VLM не использовался как источник символов или чисел.

Ручной просмотр всех шести страниц подтвердил границы отдельных таблиц и два настоящих межстраничных продолжения.

## Дальнейшие этапы

На сохранённом успешном Gate 3-результате окончательная версия маршрута дала:

- Gate 4: `CASE_COMPLETE_FOR_CURRENT_INPUT_SET`;
- один бизнес-документ;
- 121 финансовый факт;
- Gate 5: `PREPARATION_INCOMPLETE / REAL_EVIDENCE_GAPS_REMAIN`;
- потеря исходных фактов: 0;
- выдуманные факты: 0;
- расчёты без утверждённой методологии: 0;
- XML и PDF не выпущены.

Финальный единичный raw-PDF прогон на итоговой версии остановился раньше: `ndfl_gate3_document_incomplete`. Canonical при этом остался корректным. Ретрая и ремонта модельного ответа не было. Поэтому непрерывный проход одного свежего запуска до Gate 5 пока не доказан.

## Нерешённые решения методологии

Не утверждены два правила:

- как распределять комиссию покупки при частичной продаже позиции;
- на каком этапе и по какому правилу округлять промежуточные суммы в иностранной валюте.

Ограниченный поиск по официальным материалам ФНС не дал достаточно точного правила для реализации этих двух случаев. Код не подменяет отсутствующее решение предположением.
