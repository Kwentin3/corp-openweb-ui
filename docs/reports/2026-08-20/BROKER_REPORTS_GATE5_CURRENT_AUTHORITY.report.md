# Broker Reports: текущее состояние Gate 5

Дата: 2026-08-20

Статус: `READY_FOR_SERVER_DELIVERY_WITH_KNOWN_GATE3_LIMIT`

## Что закрыто

У Gate 5 оставлен один текущий владелец методики —
`Gate5TrustedMethodologyAuthorityFactory.create` — и две явно текущие версии:

- `ru-ndfl-securities-source-fact-consumption-proof@2026.7-current-authority`;
- `ru-3ndfl-2025-declaration-input-contract@2026.2-current-authority`.

Исторические ресурсы остаются только для проверки старых доказательств. Они не
выбираются текущим кодом и не являются fallback. Legacy-маршрута обработки нет.

Каждый незакрытый пункт теперь получает ровно один класс владельца причины:

- `REAL_SOURCE_EVIDENCE_MISSING`;
- `USER_CASE_FACT_MISSING`;
- `EXTERNAL_AUTHORITATIVE_FACT_MISSING`;
- `METHODOLOGY_RULE_MISSING`;
- `INTERNAL_CONTRACT_OR_PIPELINE_DEFECT`.

Внутренняя поломка не может превратиться в просьбу пользователю принести ещё
один документ. Пользователю разрешены только настоящая нехватка исходных
доказательств и отсутствующий факт его конкретного случая.

## Что показал реальный сохранённый случай

Gate 5 повторно прочитал сохранённые Gate 4 facts реального шестистраничного
брокерского отчёта без provider calls и без изменения хранилища. Девять
активных требований распределились так:

- 4 — `USER_CASE_FACT_MISSING`: налогоплательщик/период, экземпляр подачи,
  подписант и бюджетное намерение;
- 4 — `METHODOLOGY_RULE_MISSING`: источник дохода, иностранный налог,
  налоговая база группы и итоговый расчёт;
- 1 — `INTERNAL_CONTRACT_OR_PIPELINE_DEFECT`: результат по ценным бумагам
  пока содержит потерянные role bindings. В той же группе отдельно сохранены
  четыре настоящих пробела ранней истории приобретения.

Терминал — `PREPARATION_INCOMPLETE / REAL_EVIDENCE_GAPS_REMAIN`. XML и PDF не
выпущены. Это правильная остановка, а не ошибка транспорта.

## Юридический результат

Официальные источники подтверждают следующее:

- документально подтверждённые прямые комиссии относятся к расходам по
  операциям с ценными бумагами, а стоимость приобретения учитывается по FIFO;
- статья 210 задаёт дату курса ЦБ для дохода и расхода;
- порядок 3-НДФЛ задаёт масштаб денежных полей и округление рассчитанного
  налога до полного рубля;
- иностранный налог может быть зачтён только при выполнении статьи 232 и
  применимого соглашения.

Два узких вопроса не закрыты догадкой:

- официальный источник не определяет, как делить одну комиссию приобретения,
  если продана только часть приобретённого лота —
  `LEGAL_INTERPRETATION_REQUIRED`;
- порядок декларации не называет правило разрешения ровно половины копейки для
  неналогового денежного поля — `LEGAL_INTERPRETATION_REQUIRED` на этой
  границе. До неё сохраняется точный Decimal без промежуточного округления.

Брокерский отчёт доказывает только буквально указанное удержание. Для ветки
статьи 232 он сам по себе достаточен лишь тогда, когда его выдал источник
выплаты дохода, документ содержит помесячные суммы дохода и налога и выполнены
требования к копии и нотариальному переводу. Применимость и предел соглашения
остаются внешними официальными фактами; refund/reversal не сальдируются без
отдельной методики.

## Честная квалификация Gate 3

На одном замороженном Canonical, с одним текущим model/profile, словарём,
Role Pack и инструкциями выполнены три прохода. Результаты: 74, 49 и 83
финансовые аннотации. Все проходы завершились, каждый сделал ровно два provider
submission; retry, repair, fallback, best-of-N и ручной правки не было.

Итог: `CURRENT_GATE3_VARIANCE_OBSERVED_ON_FROZEN_CANONICAL`. Структура таблиц
в Canonical сохранена, но финансовая разметка текущего Gate 3 не повторяется и
не может считаться продуктово устойчивой. Это внутренний предел текущего
конвейера. Подгонка prompt по этому же документу в данную работу не входит.
