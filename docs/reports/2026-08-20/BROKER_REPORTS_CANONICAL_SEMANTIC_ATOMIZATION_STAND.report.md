# Broker Reports: Canonical Semantic Atomization Stand

Дата: 2026-08-20

Статус: `SEMANTIC_ATOMIZATION_DOES_NOT_ADD_USEFUL_BOUNDARY`

Production не изменён. Gate 2, current Gate 3, Gate 4/5, PDF pipeline,
словарь финансовых типов и серверный bundle не менялись.

## Простой вывод

Проверенная постановка не дала полезного нового слоя между Canonical и
классификацией.

Модель работала повторяемо, когда могла ссылаться только на целые элементы
Canonical. Но она почти буквально воспроизвела физическую структуру:

```text
одна строка таблицы → один атом
```

Это не решило исходную проблему. Строка с двумя явными утверждениями осталась
одним атомом, а строка сделки сохранила внутри НКД и две отдельные комиссии.
Следующая классификация не стала очевидной задачей `один атом → один код`.

## Что проверили

Использован тот же frozen Canonical с root hash, который применялся в стендах
current Gate 3 и closed classifier. Из него до первого provider call вручную
выбраны шесть небольших локальных блоков:

- заголовок как отрицательный контроль;
- три простые строки;
- строка с двумя предложениями: зачисление купона и удержание налога;
- строка сделки с НКД и двумя комиссиями.

Source truth квалифицирован до model execution. Модель не видела ожидаемые
границы и не получала финансовые labels, роли или налоговые правила.

Заранее заморожены два варианта:

1. `refs_only`: граница атома задаётся existing source refs.
2. `ref_spans`: граница задаётся source ref плюс точный дословный фрагмент
   literal внутри элемента.

Каждый вариант выполнен три раза с одинаковыми prompt, schema, model и
settings. Всего было шесть provider submissions, без retry, repair, best-of-N
или ручной правки результата.

## Machine result

Source-truth rubric содержал 9 атомов в 6 блоках.

| Метрика | `refs_only` | `ref_spans` |
| --- | --- | --- |
| Terminal responses | 3 validated | 1 validated, 2 rejected |
| Атомов в validated run | 5, 5, 5 | 5 |
| Уникальных boundary maps | 1 | 1 среди одного validated run |
| Exact source-truth atoms | 0 из 9 во всех runs | 0 из 9 |
| Полное claim coverage | нет | нет |
| Exact boundary repeatability | да | нет |

Два `ref_spans` ответа были отвергнуты fail-closed валидатором с terminal
`atomization_claim_slice_invalid`: их claim slices не прошли строгий контракт
точной привязки к Canonical. Первая версия стенда сохраняла raw output только
после validation, поэтому более узкую причину двух rejection честно установить
нельзя. Для будущих запусков сохранение raw перенесено перед validation, но эти
два запуска не повторялись. Семантического retry не было.

## Независимый аудит агентом

Вторая LLM как judge не использовалась. Агент самостоятельно прочитал frozen
Canonical и validated atomizations.

- Заголовок корректно не превратился в атом.
- Три простые строки правдоподобно стали тремя отдельными атомами.
- Строка с купоном и отдельным предложением об удержанном налоге во всех
  validated outputs осталась одним атомом. Это явная fidelity-ошибка.
- Строка сделки также осталась одним атомом вместе с НКД и двумя комиссиями.

Последний пункт допускает спор: всю строку можно считать одним событием с
атрибутами. Поэтому rubric из 9 атомов не объявляется универсальной онтологией.
Но этот спор и есть архитектурная проблема: рабочее определение атома не даёт
однозначного правила, когда колонка является атрибутом события, а когда —
самостоятельным утверждением.

Вывод не зависит от спорной строки сделки. В составной ячейке купон и налог
записаны двумя явными предложениями, но модель всё равно их склеила.

## Ответы на четыре вопроса GOAL

1. **Существует ли practically useful слой?** В проверенной постановке — нет.
   Получился повтор физической строки, а не новая полезная граница.
2. **Может ли LLM стабильно выделять атомы?** Стабильно — да, но стабильно
   неправильные. Точная внутрячеечная адресация также оказалась нестабильной.
3. **Какой минимальный контекст нужен?** Локальной строки с заголовком достаточно
   для воспроизведения строки, но недостаточно для нужного смыслового разреза.
   Whole-document запуск не оправдан и не выполнялся.
4. **Упростилась ли классификация?** Нет. Compound meanings остались внутри
   возвращённых атомов.

## Стратегический вывод

Не надо внедрять отдельный LLM atomization layer и не надо улучшать его prompt.
На этом Canonical он добавляет стоимость и новую неоднозначную семантическую
границу, но не снимает свободу со следующего classifier.

Здравое зерно сохраняется: точные source refs и локальный табличный контекст
полезны. Но разделение составного текста должно иметь более строгий,
проверяемый источник границ, чем свободное понятие «самостоятельного
утверждения». Этот стенд такого источника не доказал.

Приватные literals, source refs, ручной rubric и raw provider responses
сохранены вне Git. В репозитории находится только безопасный агрегированный
receipt:
