# Broker Reports: Gate 3 Minimal Classifier Stand

Дата: 2026-08-20

Статус: `CLOSED_MACHINE_CLASSIFIER_PROMISING`

Production не изменён. Gate 4/5, PDF parser, налоговая методика и серверный
bundle в эксперименте не участвовали.

## Простой вывод

Нынешний Gate 3 действительно даёт модели слишком большую задачу. На одном
входе модель одновременно решает:

- какие из 2 236 объектов считать финансовыми;
- сколько аннотаций вернуть, включая право вернуть пустой список;
- какой target выбрать;
- сколько meanings назначить одному target;
- а вторым model pass — куда привязать роли.

Сам Canonical при этом стабилен: один chunk, 6 nodes, 198 строк и 2 032
ячейки; потерянных и дублированных targets нет. Его model view занимает 47 705
символов. Финальный pass-1 input занимает 55 905 символов, role-pass — ещё
33 907. В response schema массива annotations нет ни нижней, ни верхней
границы.

Terminal:

```text
CURRENT_GATE3_CONTEXT_EXCESSIVE_FREEDOM_PROVEN
```

## Что проверили

Повторно не строили отвергнутый G5.92. Там код заранее перечислял целые строки,
но строка часто содержит несколько независимых source meanings; точность тогда
ухудшилась с 53/105 до 26/105.

В новом стенде объектом стала уже существующая ячейка Canonical. Заголовок
таблицы и её строка даны только как контекст. Никаких новых source objects или
financial meanings модель создавать не может.

Использованы все 12 meanings текущего Dictionary 2.0.0, только под короткими
машинными ID `F01..F12`. `F00` означает `UNMAPPED`. Это индекс существующего
словаря, не новая онтология.

Вручную по Canonical квалифицированы 24 ячейки:

- 16 простых одно-смысловых объектов: покупка, продажа, комиссия и купон;
- 8 объектов должны дать `F00`: заголовки, position/общий текст, неявная
  «сделка» и две compound-ячейки с купоном и удержанным налогом одновременно.

Контракт требует ровно 24 ответа в исходном порядке и ровно один code на
объект. Неизвестный, повторный, пропущенный или переставленный object отвергает
весь ответ. Role pass отсутствует.

| --- | --- | --- |
| Source-truth correct | 21, 15, 18 из 24 | 22, 22, 22 из 24 |
| Явные ответы модели | 17, 9, 14 из 24 | 24, 24, 24 из 24 |
| Уникальные карты за 3 запуска | 3 | 1 |
| Provider submissions | уже замороженные 2 на полный run | 1 на run, всего 3 |
| Invented/omitted objects | current sparse omission allowed | 0 / 0 |
| Retry/repair/best-of-N | 0 / 0 / false | 0 / 0 / false |

Closed classifier дал одну и ту же карту во всех трёх запусках. Completeness
стала детерминированной: вход 24, выход 24. Средняя точность на маленьком
source-truth наборе выросла с 75% до 91,7%.

Но два промаха также повторились трижды. Обе compound-ячейки буквально
сообщают сразу купон и удержание налога. По контракту одного кода они должны
были получить `F00`, а модель стабильно выбрала только `COUPON_INCOME`. Значит
ограничение количества объектов решено, но один code не способен без потери
представить compound source object.

Более сильный terminal не ставится: exact mapping repeatability доказана только

## Что это значит для стратегии

Главная причина разброса current Gate 3 — не только «характер LLM», а свобода
самой постановки: модель владеет discovery, cardinality, meaning и role binding
одновременно.

Паттерн `существующий object → один closed ID` заметно улучшает ситуацию для
действительно атомарных объектов. Рассматривать его как направление можно, но
не как готовую замену production Gate 3.

Следующая развилка находится перед classifier:

> может ли deterministic runtime показать модели действительно атомарные
> source assertions, не придумывая смысл и не разрезая compound text по
> догадке?

Пока этого доказательства нет, расширять стенд в production или добавлять
prompt-правила по двум найденным ячейкам нельзя.

## Честная история запуска

- первый preflight остановился до provider call из-за недоступности моделей при
  проблеме VPN;
- после перезапуска VPN exact Gemini model снова появилась;
- ещё два локальных pre-semantic запуска остановились на форме штатного
  transport/schema; исправлялась только упаковка под существующий adapter;
- после появления первого semantic response prompt, 24 source objects, code
  catalog и source truth не менялись и по ответам не подгонялись;
- финальный цикл получил ровно 3 terminal semantic responses.
