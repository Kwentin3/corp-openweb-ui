# OfficeCLI: квалификация неохваченных профилей

Дата: 2026-09-26. Итог: GPT 6 Luna, GPT 6 Sol и Claude Opus 5.5 включены
в существующий native OfficeCLI Filter после продуктовой проверки. Antigravity
не включён: провайдер не поддерживает function calling для опубликованного ID.
Теперь оба модельных valve содержат 12 профилей: прежние девять и три новых.

## Реальные проверки

| ID | Интерфейс и роль | Результат |
| --- | --- | --- |
| `gpt-6-luna` | Обычный чат, `admin` | PASS после существующего исключения `reasoning_effort=none` |
| `gpt-6-sol` | Обычный чат, `admin` | PASS после того же исключения |
| `claude-opus-5-5` | Обычный чат, `admin` | PASS без дополнительной адаптации |
| `models/antigravity-preview-latest` | Обычный чат, `admin` | FAIL: HTTP 400, `Function calling is not enabled for models/antigravity-preview-latest` |

Под временным обычным пользователем каталог содержал 11 видимых профилей:
прежние девять OfficeCLI и два специализированных NDFL/Pipe. Все четыре новых
ID отсутствовали. Поэтому их проверили в обычном интерфейсе чата под существующим
администратором, которому эти модели уже доступны. Access grants, роли моделей
и видимость каталога не менялись. Временный пользователь удалён до отправки
сообщений и загрузок. Эти три PASS не являются новой проверкой под `role:user`;
прежние девять имеют отдельную пользовательскую матрицу в
[первоначальном отчёте](OFFICECLI_ALL_PUBLISHED_MODELS.report.md).

Каждый успешный новый профиль сам инспектировал два загруженных fixture XLSX
по штатным file IDs и создал один результат через `create_office_spreadsheet`.
Files metadata/content API вернули 200, владельцем результата остался автор
чата. Скачанные байты проверены против исходных `jan.xlsx` и `feb.xlsx`:
ровно листы «Янв26», «Фев26», 4 × 4 ячейки, все исходные значения, заголовки,
формулы D2/D3/D4, «Итого», пустые B4/C4, вычисленные из исходников итоги 350/550.
Это проверка текста формул и независимый расчёт итогов, не тест пересчёта Excel.
Матрица, native receipts, XLSX и повторяемый validator находятся в
[artifacts/officecli-catalog-expansion](artifacts/officecli-catalog-expansion/acceptance.json).

До исключения reasoning оба GPT 6 вернули конкретную ошибку Chat Completions:
`Function tools with reasoning_effort are not supported ... set reasoning_effort to 'none'`.
Применён существующий `multi_xlsx_no_reasoning_model_ids`, без нового клиента
или переключения API. Теперь он содержит `gpt-5.6-luna,gpt-6-luna,gpt-6-sol`.
Явно заданный иной effort по-прежнему вызывает объяснимую ошибку; одиночное
вложение не получает этот override. Antigravity после неудачи удалён из обоих
модельных valves; переписывание схемы tools не объявлено решением отказа провайдера.

## Старый чат: незавершённая проверка

Оригинальный чат `1a1666bc-caf6-4d91-b177-ed6a0fc4114c` не изменялся. Его штатная
копия сохранила 29 исходных file IDs и была продолжена без повторной загрузки.
Задание требовало только полный перечень вкладок двух книг в новом XLSX,
включая служебные листы и соседние месяцы; финансовые данные не переносились.

Браузер показал native inspect/create. В 12:08:54 UTC Tool Server вернул 422:
66 команд при лимите 64. В 12:10:20 kernel MEMCG OOM убил `python3` основного
OpenWebUI при лимите RAM 3 GiB и swap 1 GiB. В 12:10:24 существующая restart
policy автоматически запустила тот же контейнер/образ. Ручного перезапуска
или изменения ресурсов не выполнялось. После восстановления health и
authenticated API вернули HTTP 200; сохранённый ответ остался `done=false`
без вложения. Этот сценарий имеет статус **FAIL / не квалифицирован**.

Точная причина роста памяти не установлена. Временная близость запроса и OOM
не доказывает виновность конкретного RAG/tool шага; тяжёлый запрос повторно
не запускался. Диагностика и самостоятельная приёмка заведены в
[issue #527](https://github.com/Kwentin3/corp-openweb-ui/issues/527).
Двухфайловые canaries не доказывают выполнение исходного объединения всех
29 финансовых книг. Правила включения служебных/соседних месячных листов
также должны быть определены для этого отдельного задания.
