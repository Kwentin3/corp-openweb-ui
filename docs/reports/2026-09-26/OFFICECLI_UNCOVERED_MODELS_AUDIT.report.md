Исторический снимок **до** квалификации новых профилей. Итоговая конфигурация,
фактические ограничения провайдеров и результаты последующих проверок:
[расширение каталога](OFFICECLI_CATALOG_EXPANSION.report.md).

Дата: 2026-09-26. Read-only аудит production через существующую браузерную
сессию и штатные API. Конфигурация, исходные файлы и чат не изменялись;
новых сообщений, запросов провайдерам, перезапусков и развёртываний не было.

Обезличенные технические результаты:
[матрица охвата](artifacts/officecli-coverage-audit/coverage.json) и
[проверка исходных книг](artifacts/officecli-coverage-audit/input-findings.json).
Текст интервью, значения финансовых ячеек, бинарные исходники и данные
пользователей в эти артефакты не включены. Временные скачанные копии удалены
после сохранения результатов; исходники в OpenWebUI не затрагивались.

## История проблемного чата

Чат: https://gpt.alpha-soft.ru/c/1a1666bc-caf6-4d91-b177-ed6a0fc4114c.
Первое сообщение от 23 сентября содержит 29 Excel-вложений. Задание:
объединить ежедневные вкладки в одну месячную вкладку каждого файла, названия
месячных вкладок — «Мес ГГ».

Старый ответ `gpt-5.6-luna` от 23 сентября сообщает HTTP 422 из-за нескольких
XLSX без выбранного `file_id`; он предшествует исправлению 26 сентября.
Ответы после развёртывания от 26 сентября идут от другого ID — `gpt-6-luna`.
Они сохраняют текстовые RAG sources, но не содержат native function-call output
или выходного файла. Последний ответ предлагает Python-скрипт вместо результата.
В сохранённой конфигурации чата нет явно записанного выбора tools; полная
историческая исходящая схема tools не получена. Подтверждённые факты — отсутствие
ID в live Filter и отсутствие результата, а не побайтная реконструкция запроса.

Повторно загрузить файлы для устранения этого пробела не требуется: две
проверенные исходные книги доступны через Files API и корректно открываются.
Доступность байтов остальных 27 файлов этим аудитом не квалифицирована.

Обе книги скачаны через `/api/v1/files/{id}/content` с HTTP 200. SHA-256 байтов
совпадает с сохранённым `meta.file_hash`; книги прочитаны локально без изменений.

Январский файл: ID `78c06639-1978-4fd1-b719-d63790307045`,
SHA-256 `9bbe6a1fad13e8f157faa78a1cd8016412fe1dcc54052d1d1e86780b9cb706f1`.

Сохранённые ответы используют примерно 2.6–3 тысячи символов выбранных фрагментов
этих книг, а не полную структуру всех листов. Начало последнего извлечения каждой
книги найдено в фактических ячейках соответствующего исходника. Для последних
ответов не обнаружена подмена этих фрагментов чужим файлом. Проверка начала
фрагментов не доказывает полноту всего retrieval или всех 29 источников.

Названия файлов также не гарантируют месячный состав листов: в январском есть
февральские листы, в июльском — августовские и служебные. Для точной реальной
сборки нужно определить правило включения таких листов; двух простых fixture-книг
из прошлой квалификации недостаточно для утверждения о полном переносе этой задачи.

## Необходимое продолжение

Квалифицировать четыре пропущенных профиля через существующий Tool Server/Filter,
затем добавить только успешно проверенные ID в оба valves. Для `gpt-6-luna`
отдельно подтвердить продолжение этого старого чата с уже загруженными файлами.
Приёмка — реальное чтение нужных исходников и скачанный результирующий Excel,
сверенный с исходными ячейками и согласованным составом листов.

Автоматическое включение по маске `gpt-*`/`claude-*` не предлагается: наличие
модели в каталоге не доказывает совместимость её tools, reasoning и истории.
Конфигурация в этом аудите не изменялась.
