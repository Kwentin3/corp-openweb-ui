# OpenWebUI host flight recorder — 2026-09-26

Реализован согласованный KISS-этап: отдельный systemd-сервис на хосте сохраняет
события Docker, OOM-факты ядра, безопасную проекцию access/error logs и ресурсы.
Основной контейнер OpenWebUI не пересоздавался и не перезапускался; его RestartCount
сохранился равным 1, лимит памяти 6 ГиБ. Образ сохранился:

## Квалификация

- 8 stdlib unit tests: удаление секретов/query/path, события без Docker labels/exec
  arguments, OOM vs exit 137, восстановление карточки после открытия сохранённого
  хранилища, retention по времени/объёму и часовая ротация.
- Отдельный реальный контейнер без сети и томов приложения, 64 МиБ RAM, без swap:
  ручной restart/exit 137 и OOM получили разные доказательства. Kernel указал PID
  и RSS; Docker независимо сообщил oom и OOMKilled=true. Нехватка памяти
  ограничена тестовым cgroup; основной OpenWebUI продолжил работу.
- Сам тестовый сборщик перезапускался; доаварийная история и незаконченные карточки
  пережили перезапуск. Двухминутное постокно завершилось в сохранённых карточках.
- Access-запись `spreadsheets.create`/HTTP 422 сохранена, маркер секрета из query
  отсутствует во всех файлах тестового хранилища. Это синтетическая log-проверка,
  не новый вызов OfficeCLI или провайдера модели.
- Первоначальный TasksMax=32 оказался недостаточен для Go threads Docker CLI;
  исправлен на 128. В окончательном unit регулярные снимки и чтение источников
  проходят без ошибок. Измеренный пример: ~46 МиБ RAM, пик ~55 МиБ; это наблюдение,
  не гарантия максимальной нагрузки. Установлены MemoryMax=192M и CPUQuota=10%.

Хранение: история до 7 дней/256 МиБ, карточки до 30 дней/64 МиБ; применяется более
раннее ограничение. Данные находятся только в root-owned каталоге хоста. Сохранённые
технические поля не включают тела чатов/документов или токены. Публичный пример
инцидента содержит только синтетический canary и безопасные технические показатели.

Ограничения: нет уведомлений во внешние каналы, OTel и изменений upstream core.
Существующие HTTP access logs не дают полного chat/tool trace, поэтому виновник
роста памяти по одной временной близости не назначается. Код 137 остаётся unknown
без отдельного OOM-доказательства. Пропуски при простое и сокращение длинного timeline
описаны в runbook. Исходные Docker logs имеют отдельные правила хранения.

8 тестов самописца выполнены отдельно локально и на Linux-хосте. Обязательный CI
выполняет существующие проверки репозитория; его workflow сохранён без изменений,
так как текущий GitHub credential не имеет scope для изменения workflows.
Внедрение использует штатные Docker/Linux/systemd интерфейсы, без новых Python dependencies.
