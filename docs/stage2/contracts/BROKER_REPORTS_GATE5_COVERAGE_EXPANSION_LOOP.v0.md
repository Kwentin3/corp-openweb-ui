This contract owns only the G5.37 evidence-driven coverage loop. It does not
replace or weaken any Gate 1–5, supplied-case completeness, declaration,
projection, XML or official-XSD authority.

## One unchanged vertical

Every admitted sample starts at a real source boundary and uses the existing
owners:

```text
source bytes / authenticated OpenWebUI upload
→ Gate 1 normalization and persistence
→ canonical Gate 2 reader
→ Gate 3 provider proposal plus deterministic validation
→ Gate 4 normalized Financial Case
→ existing Gate 5 factories
→ trusted Projection Definition
→ XML
→ packaged official XSD
```

A corpus fixture, test or browser harness may supply transport and explicit
synthetic case facts. It may not construct a Gate 2/3/4 result, Tax Model,
Declaration Package, semantic input or XML directly.

## Corpus authority

The first-wave corpus is the versioned
[`g537_coverage_corpus.v0.json`](../../../services/broker-reports-gate1-proof/tests/fixtures/g537_coverage_corpus.v0.json).
For every sample it binds the source classification, format, tax period,
privacy status, content hash, expected economic event and evidence origin.

Synthetic pressure fixtures are explicitly synthetic and make no broker
format claim. Raw bytes of an official/public report may remain outside Git;
the corpus retains its official origin and content hash.

## Iteration contract

For each independent sample:

1. run the existing product entrypoint as far as possible;
2. retain the first real blocker;
3. classify the correct owner;
4. apply the smallest owner-local correction;
5. replay from source/upload;
6. replay the baseline and all prior supported samples;
7. record `REPORT_SUPPORTED` or `STRATEGIC_STOP` in the coverage ledger.

The minimum root-cause classes are representation, structural extraction,
financial semantic labeling/modeling, tax semantics, declaration coverage and
product integration.

## Source transport boundary

The G5.35 source envelope accepts exactly one hash-bound representation:

```text
content_utf8
or
content_base64
```

Base64 must decode strictly, re-encode canonically and match the declared
source SHA-256. This is a representation boundary only. It must not introduce
broker vocabulary, financial labels, tax rules or target mapping.

## Canonical convergence

Different representations of the same financial event must converge to
equivalent Gate 4 business semantics and unchanged downstream declaration
semantics. Provenance may differ. With equal supplied-case values, Tax Model,
Declaration Semantic Input and XML meaning must not vary because of filename,
MIME type, worksheet, table layout, source vocabulary or broker identity.

## Required negatives

- an incomplete role remains `role_incomplete`; missing values are not zero;
- provider output remains a proposal subject to schema, literal, source and
  role validation;
- an unsupported new financial meaning is not relabeled as a supported one;
- a missing Tax Model or trusted declaration obligation is a strategic/domain
  blocker, not a parser fix;
- binary bytes with malformed base64 or a hash mismatch fail closed;
- no new report may regress the G5.36 CSV baseline.

## Product proof requirement

At least one new document class must cross the real authenticated OpenWebUI
upload/chat/provider/download boundary and end in byte-stable, official-XSD-
valid XML. A local canonical-convergence proof alone is insufficient for that
class.

## Anti-drift and scope stop

G5.37 admits no broker adapter family, broker-specific tax branch, new
database/registry, synonym framework, Gate-owner bypass, validator weakening,
case-time LLM tax authority, manual XML, defaulted missing fact or production
activation.

The final anti-drift check is:

> Does the change make another document converge to the stable financial
> semantics, or does it start a separate system for one broker?

After `COVERAGE_EXPANSION_LOOP_PROVEN`, stop. Further corpus expansion is a
separate authorized goal.
